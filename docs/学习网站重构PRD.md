## 1. 产品概述

### 1.1 项目背景

当前仓库是一套完整的 Agent Harness 工程课程，以 17 个渐进章节解释一个 Coding Agent 如何从最小循环成长为具备权限、规划、上下文压缩、记忆、任务系统、团队协作、MCP、Workflow 和 Goal Loop 的完整运行载体。

仓库已经包含一个 Next.js 学习平台，具备双语课程、源码、模拟、架构、差异比较等基础能力。本次重构不改变知识主题，而是重新设计内容呈现方式和视觉体验，使网站从“课程资料查看器”升级为具有鲜明品牌、清晰学习路径和更强沉浸感的数字学习产品。

### 1.2 产品定位

> 一个以代码、消息流和系统结构为核心视觉语言的 Agent Harness 交互学习站。

网站不提供账号体系，不承担云端学习记录，不在线运行真实 Agent，也不作为生产级 Agent 工具。它只负责把仓库中的知识讲清楚、展示清楚、关联清楚。

### 1.3 核心价值

1. **建立正确心智模型**：让读者理解“模型负责决策，Harness 负责提供环境”。
2. **降低源码阅读门槛**：把 17 个章节之间的机制增量转化为可视化路径。
3. **把抽象循环变成可观察过程**：通过消息流模拟、架构图、代码注释和差异对比解释运行行为。
4. **同时满足顺序学习和按主题查询**：既能从 `s01` 学到 `s17`，也能按 Tools、Planning、Memory、Concurrency、Collaboration 查阅。
5. **形成独特品牌体验**：采用参考站的“黑色蓝图 / Editorial Tech”气质，但使用 Agent Loop、工具调用和消息节点形成自己的视觉识别。

## 2. 目标与非目标

### 2.1 产品目标

- 构建一个视觉统一、阅读舒适、结构明确的课程主页和章节学习体验。
- 完整承载当前 17 章主线内容，不混入旧版 12 章编号。
- 保留并强化现有的学习、模拟、源码和深度解析能力。
- 让用户在任意页面都能知道：当前章节、所属阶段、前置知识、下一步和整体进度。
- 仅支持英文和简体中文；首页和站内界面随语言完整切换，切换后仍停留在当前章节或功能页。
- 在桌面端形成沉浸式“工程蓝图”体验，在移动端保持清晰、可操作和可阅读。
- 不依赖登录即可使用全部核心内容。
- 使用 `localStorage` 记录本机阅读进度，并明确该进度不会上传或跨设备同步。

### 2.2 非目标

本期不包含：

- 登录、注册、用户账户和云端进度同步；
- 评论、点赞、收藏、社区和课程付费；
- 在线执行真实 Shell、Python 或 Agent；
- 浏览器端调用大模型或接收用户 API Key；
- 在线代码编辑器、沙箱和评测系统；
- 后台 CMS；
- 全局搜索；
- 旧版 `agents/` 和旧版 12 章文档的展示、导航和兼容页面；
- 日语内容、日语路由和日语界面；
- 部署、域名、服务器、CDN、CI/CD 和上线策略。

### 2.3 可选增强项

以下能力不要求登录，可作为后续增强：

- 本地书签；
- 最近阅读章节；
- 复制代码后的本地反馈；
- 不上传服务器的界面偏好，例如语言、字号和动效开关。

## 3. 目标用户

### 3.1 主要用户

| 用户类型 | 特征 | 核心需求 |
|---|---|---|
| Agent/Harness 初学者 | 理解 LLM，但没有完整实现过 Agent Loop | 从最小循环开始建立系统认知 |
| Python 开发者 | 能读代码，希望实现自己的 Coding Agent | 查看工具分发、权限、状态和并发实现 |
| AI 应用工程师 | 已使用模型 API，关注工程化能力 | 快速查找 Memory、Task、MCP、Workflow 等机制 |
| 技术课程学习者 | 偏好图示、步骤和可交互演示 | 低门槛理解消息流与组件关系 |
| 架构研究者 | 不一定逐章运行代码 | 比较章节差异并理解设计决策 |

### 3.2 用户使用场景

1. 第一次进入网站，希望在 30 秒内知道课程讲什么、适合谁、从哪里开始。
2. 按顺序阅读 17 章，每章查看叙事、源码、模拟和架构。
3. 通过课程顺序或主题分类查找“上下文压缩”“Worktree”“Goal Loop”等概念并进入对应章节。
4. 比较 `s04` 和 `s15`，理解 Hooks 如何进入集成 Harness。
5. 在移动设备上阅读课程正文和代码片段。
6. 从某篇外部链接进入单章后，快速了解它在整体路径中的位置。

## 4. 仓库内容总结

### 4.1 核心理念

仓库采用以下基本模型：

```text
Agent 产品 = 模型 + Harness

Harness = Tools + Knowledge + Observation + Action Interfaces + Permissions
```

基础 Agent Loop 为：

```text
用户请求
→ messages[]
→ 模型响应
→ 是否包含 tool_use？
  ├─ 是：执行工具 → 追加 tool_result → 再次调用模型
  └─ 否：结束本轮或进入 Goal 判断
```

网站所有内容组织和可视化都应围绕这条主轴，而不是把 17 章展示为互不相关的文章列表。

### 4.4 内容版本边界

新网站必须明确：

- 根目录 `s01`—`s17` 是唯一主课程；
- 旧版 12 章不出现在新界面的课程路径、主题页、比较页和章节前后导航中，也不要求提供旧页面兼容入口；

- `s16` 是可恢复编排；
- `s17` 单独演示 Goal Stop Hook，概念上可与集成宿主组合，但不是第二个全量 `s15`。

## 5. 参考网站风格总结

### 5.1 风格关键词

对 Hyperstudio 源站及其 Refero 风格说明的综合概括：

> **Blueprint scratched into obsidian** —— 在黑曜石上刻出的工程蓝图。

主要关键词：

- 深黑画布；
- Editorial Tech；
- 大字号、常规字重、负字距；
- 细线网格和结构边框；
- 极低装饰度；
- 无投影、无渐变；
- 白色作为唯一强动作色；
- 暖金色作为方向性图标色；
- 荧光绿仅用于在线或活跃状态；
- 大量留白与克制的微交互；
- 图形来自点阵、线框和几何结构，而非摄影。

### 5.2 源站观察

源站首页呈现出以下特征：

- 页面背景接近纯黑，正文和容器主要通过细线分隔，而非卡片底色和阴影；
- 桌面端主标题约 63px、字重 400，移动端约 52px，层级主要由尺寸而不是粗体建立；
- 顶部导航固定，使用半透明 Carbon 黑背景；
- Hero 使用白色点阵地图形成视觉焦点；
- 主按钮为白色填充胶囊，次按钮为深色/描边按钮；
- 服务内容在桌面端形成规则网格，移动端纵向堆叠并保留边框结构；
- 区块间距很大，整体节奏接近数字杂志或设计作品集；
- 链接交互以透明度变化为主，常见过渡约 200ms；
- 移动端保留大标题和固定导航，减少导航项而不缩小核心表达。

#### 色彩

| Token | 色值 | 参考角色 | 在学习网站中的角色 |
|---|---|---|---|
| Obsidian | `#101010` | 页面画布 | 全站主背景 |
| Carbon | `#080808` | 深层表面、Hero | Header、Hero、代码深层背景 |
| Graphite | `#212121` | 结构细线 | 分隔线、卡片边框、网格 |
| Card Slate | `#3b3d45` | 提升层边框 | Hover、激活容器边框 |
| Iron | `#474747` | 次级描边 | 控件描边、禁用状态 |
| Chalk | `#f3f3f3` | 主文本 | 标题、正文高优先级信息 |
| Smoke | `#9c9c9c` | 次文本 | 说明、摘要、辅助信息 |
| Ash | `#c1c1c1` | 三级文本/边线 | 小标题、代码辅助信息 |

| Pulse Green | `#98ff38` | 活跃状态 | 当前章节、运行中、已连接状态点 |

#### 字体

参考系统使用 Aeonik 作为主字体、Input 作为元信息字体。本项目虽然不计划商用，但仍需遵守字体的复制与再分发许可；开源发布并不自动获得任意字体的分发权。为了让用户克隆 GitHub 仓库后即可稳定运行，并保留具有设计感的 Editorial Tech 气质，确认采用可随项目分发的开源字体方案：

```text
品牌字标与西文 Display：Space Grotesk
西文正文与界面：Space Grotesk / Inter
中文字体：Noto Sans SC / PingFang SC / Microsoft YaHei
等宽字体：JetBrains Mono / IBM Plex Mono / SFMono-Regular
```

Space Grotesk 采用 SIL Open Font License 1.1，可在满足许可证条件的前提下与软件一起嵌入和再分发。实施时优先将所需的 WOFF2 字重随项目自托管，并保留字体版权声明和 `OFL.txt`，避免依赖外部字体 CDN；中文内容使用中文字体回退，不强行套用西文字体。

设计原则：

- Display 和章节大标题统一使用 `font-weight: 400`；
- 不依赖粗体制造层级；
- 英文大标题使用轻微负字距；
- 中文标题不使用过度负字距，避免影响字形；
- 元信息、状态、工具名、章节编号和代码使用等宽字体；
- 正文保证足够行高，不能照搬作品集式紧行高。

|---|---:|---|
| 基础单位 | 4px | 所有间距为 4 的倍数 |
| 标签圆角 | 4px | 章节 ID、状态标签 |
| 卡片圆角 | 8px | 内容卡、代码框、展开面板 |

| 页面最大宽度 | 1200px | 营销首页和主内容框架 |

### 5.4 参考风格的 Do / Don't

#### 应该采用

- 使用 1px Graphite 细线建立结构；
- 使用尺寸和空间建立信息层级；
- 让主标题保持 400 字重；
- 仅将白色胶囊用于最高优先级动作；
- 金色只用于图标、路径和结构提示，不作为大面积背景；
- 绿色只用于“当前、运行中、可用、成功”等状态点；
- 使用点阵、消息节点、连线和字符图构成主视觉；
- 通过透明度、边框和文字颜色表现 Hover 与选中状态。

#### 不应采用

- 不使用投影制造悬浮层级；
- 不使用大面积彩色渐变；
- 不把所有卡片都做成胶囊或超大圆角；
- 不使用粗重 Display 标题；
- 不用多彩 Layer Badge 破坏克制色系；
- 不使用与 Agent/Harness 无关的图库照片；
- 不逐像素复制 Hyperstudio 的点阵世界地图、品牌图标或文案；
- 不为了风格牺牲长文、代码和中文阅读体验。

## 6. 新网站设计方向

### 6.1 设计命题

> **把 Agent Harness 的运行机制刻进一张可探索的黑色工程蓝图。**

参考站的“黑色画布 + 点阵世界地图”应转译为本项目自己的内容视觉：

- 点阵不再构成世界地图，而构成 `messages[]`、工具节点、Task DAG 或 Agent 拓扑；
- 金色不表示品牌奢华，而表示 Harness 提供的路径、接口和边界；
- 绿色状态点表示当前学习位置、活跃工具和已完成步骤；
- 横纵细线模拟系统总线、时间轴和代码结构；
- 大标题用于提出每章的核心问题；
- 代码、工具结果和消息流成为页面主视觉，而不是附属内容。

### 6.2 品牌确认

产品最终品牌名统一为：

```text
Harness
```

`Harness` 不随语言翻译，也不再使用 `Learn Claude Code` 作为并列品牌名。辅助标题和说明文案随当前语言完整切换。

建议英文与中文辅助标题：

```text
Build the Harness. Let the Model Drive.
构建 Harness，让模型真正行动。
```

建议品牌短句：

```text
17 LESSONS · ONE LOOP · FULL HARNESS
```

### 6.3 体验原则

1. **内容先于装饰**：视觉必须帮助理解 Agent Loop，而非形成无意义科技感。
2. **渐进披露**：首页讲价值，课程页讲顺序，章节页逐层展开细节。
3. **一处只回答一个问题**：每个区块都以“问题—机制—结果”组织。
4. **状态始终可见**：当前章节、当前 Tab、当前模拟步骤必须明确。
5. **文本和代码同等重要**：叙事解释与实现源码之间可以快速切换。
6. **克制但不静止**：使用短促、有目的的动画展示信息流动。

## 7. 信息架构

### 7.1 顶级导航

顶级导航直接对应仓库的主要内容能力，避免 `PATH`、`LAYERS` 等需要额外解释的产品术语：

```text
HARNESS（Logo，返回首页）
课程 COURSE（s01—s17 顺序学习）
主题 TOPICS（按机制浏览）
比较 COMPARE（章节差异）
语言 LANGUAGE
开始 S01 START S01
```

导航文字随当前语言完整切换；仅品牌名 `Harness`、章节编号和代码标识保持不翻译。桌面端显示完整导航，移动端保留 Logo、当前章节/进度和菜单按钮。全局搜索暂不进入导航。

### 7.2 页面结构

```text
/{locale}/                    首页
/{locale}/course              17 章课程路径
/{locale}/topics              按机制主题浏览
/{locale}/compare             任意章节比较
/{locale}/{version}           章节详情
```

- 精简后仍需保持“问题—机制—结果—边界”的完整逻辑，并确保代码示例前后可理解；
- 不夸大 Agent 能力；
- 明确区分模型、Agent、Harness 和 Workflow；
- 避免泛化的“AI 革命”“无限可能”等营销套话；
- 课程正文仍以仓库 README 为单一内容源，不在前端另行手写 17 份精简副本；如需精简，应修改对应英文和中文源 README，并同步检查两种语言的结构与技术事实。

## 15. 内容与前端数据要求

### 15.1 章节数据模型

每章至少包含：

```text
id

所属阶段/机制层
```

### 15.2 数据来源原则

- 根目录课程是单一事实来源；
- 内容生成过程应继续自动提取，不手工复制 17 份源码；
- 首页不应一次加载全部章节完整源码；
- 章节源码、Diff 和模拟数据应按页面或视图按需加载；
- 路径、标题和语言之间必须有稳定映射；
- 内容提取失败时应在开发阶段显式报错，不能生成空章节。

### 15.3 现有能力复用

优先复用现有：

- `extract-content.ts` 的章节扫描、README 改写和源码提取；
- `VERSION_META` 与 `LEARNING_PATH`；
- `scenarios`、`annotations`、`execution-flows`；
- Markdown 渲染；
- 现有 Simulator、Source Viewer、Diff 和 Architecture 数据逻辑。

视觉层和页面结构可以重做，但不应无理由重写已经验证过的内容解析逻辑。

## 17. 阅读性能与体验要求

本节仅定义产品体验，不涉及部署方案。

- 首页首屏不加载 17 份完整源码；
- 大型 SVG 和交互图按视口或 Tab 延迟加载；
- 首页模拟优先使用合成友好的 `transform` 和 `opacity`，避免因动画产生持续布局抖动；
- 字体必须提供回退栈，字体未加载时页面仍可阅读；
- 切换 Tab 时避免整页刷新；
- 长代码使用虚拟化或合理分段时，必须保持浏览器查找和行号定位可用；
- 页面布局不能因字体或图片加载发生明显跳动；
- Markdown 标题锚点稳定，可被复制和直接访问；
- 深色背景下滚动条应低存在感但仍可识别。

## 18. 验收标准

### 18.1 首页

- 用户无需滚动即可看到课程主题、17 章信息和开始入口；
- Hero 视觉明确表现 Agent Loop，而不是通用科技背景；

- 桌面和移动端均无文字遮挡、溢出和固定 Header 冲突；
- 页面不存在投影卡片和彩色渐变滥用。

### 18.2 课程页

- 完整显示 s01–s17 且顺序正确；
- 每章可进入详情；
- 阶段划分和章节边界说明准确；
- 本机进度可以记录、显示和由用户确认后清除；
- 新界面不展示旧版 12 章内容或兼容入口。

### 18.3 章节页

- 英文和简体中文均能加载对应 README；
- Learn、Simulate、Source、Deep Dive 均可访问；
- 源码与仓库当前 `code.py` 一致；
- 模拟步骤可播放、暂停、前进和重置；
- 当前 Tab、当前小节和前后章节明确；
- 移动端代码可横向滚动且不遮挡导航。

### 18.4 Compare

- 可选择任意两个章节；
- 工具、类、函数和 LOC 差异计算正确；
- 源码 Diff 可读；
- 差异不只依赖红绿色表达。

### 18.5 视觉

- 品牌统一显示为 `Harness`，品牌字标与西文 Display 使用 Space Grotesk；
- 主背景、文字、边框、金色和状态绿符合 Token；

- 卡片最大 8px 圆角；

- 主要区块由 1px 细线和空间建立层级；
- 图形语言为 Agent 节点、消息流、代码和系统总线，而非复制参考站资产。

### 18.6 响应式与可访问性

- 规定的六类视口通过检查；
- 所有核心操作支持键盘；
- Reduced Motion 生效；
- 200% 缩放下核心流程可用；
- 图片、图示、按钮和 Tabs 具备正确语义或替代文本。

## 20. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 过度模仿参考站 | 缺少自身品牌，可能形成视觉复制 | 只继承设计原则，主视觉改为 Agent Loop 与消息流 |
| 深色风格影响长文阅读 | 用户阅读疲劳 | 控制正文宽度、提高行高、使用暖白和 Smoke 分层 |
| 大标题占据过多移动空间 | 首屏看不到行动入口 | 移动端控制在 48–52px并压缩 Hero 间距 |
| 17 章源码数据过大 | 首页和切换变慢 | 页面级、Tab 级按需加载 |
| 中英文标题长度不同 | 导航和卡片溢出 | 为中文和英文分别测试，不依赖固定字符宽度 |
| 交互可视化喧宾夺主 | 用户忽视课程正文 | 动画可暂停，默认克制，始终配文字解释 |
| 旧版内容混入新界面 | 用户混淆章节编号 | 内容提取、路由和导航只接入根目录 17 章主线 |
| 字体许可文件缺失或中文覆盖不足 | 开源再分发不完整，或中英文显示不稳定 | 从 Space Grotesk 官方仓库引入 WOFF2，随项目保留 OFL 许可，并准备完整中文回退栈 |
| 金色和绿色对比度不足 | 可访问性下降 | 不作为小正文颜色，状态同时使用文字和图标 |

### 21.1 关于字体许可与开源发布的说明

不商用不等于可以使用或公开分发任何字体。字体文件本身受许可证约束，而把字体文件提交到公开 GitHub 仓库属于再分发行为；是否收费通常不是唯一判断条件。因此，本项目应选择明确允许嵌入和再分发的字体，而不是仅依据“非商业用途”选字体。

本项目最终选择 [Space Grotesk](https://github.com/floriankarsten/space-grotesk)。其官方仓库声明采用 [SIL Open Font License 1.1](https://github.com/floriankarsten/space-grotesk/blob/master/OFL.txt)，允许字体随软件嵌入和再分发，但发布时必须保留相应版权声明和许可证。这样既能保持鲜明的技术与编辑设计感，也方便用户克隆仓库后直接运行，不依赖第三方字体服务。

## 22. 最终产品判断标准

重构成功不应只表现为“网站变黑、标题变大”。最终网站需要同时满足：

- **一眼可识别**：视觉属于 Agent Harness 课程，而不是套用的暗色模板；
- **一眼可理解**：用户知道课程从一个循环成长到完整 Harness；
- **一路可追踪**：用户始终知道当前位置和下一步；
- **一层可深挖**：每章都能在叙事、模拟、源码和架构之间切换；
- **一套内容源**：网站与仓库课程保持同步；
- **一种克制风格**：黑色画布、常规字重、细线结构、少量金色和状态绿贯穿始终。

产品最终应呈现为：

> **一本可以运行、比较和探索的 Agent Harness 黑色工程手册。**
