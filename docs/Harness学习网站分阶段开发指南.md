# Harness 学习网站分阶段开发指南

## 文档信息

| 项目 | 内容 |
|---|---|
| 文档用途 | 将重构 PRD 转换为可分会话执行、可独立验收的开发阶段 |
| 需求依据 | [`docs/学习网站重构PRD.md`](./学习网站重构PRD.md) v1.2 |
| 实施目录 | `web/` |
| 技术栈 | Next.js 16、React 19、TypeScript、Tailwind CSS 4、Framer Motion |
| 内容主线 | 仓库根目录 `s01_*`—`s17_*` |
| 本期明确不做 | 全局搜索、登录与云端进度、旧版 12 章界面、部署与上线 |

## 1. 使用方式

本指南将开发工作划分为 **6 个阶段**。每个阶段都是一个较完整的交付单元，不再拆成大量零散任务。前五个阶段完成产品基线，第六阶段再根据用户确认的偏好进行个性化调整。

执行约定：

1. 新会话开始时先阅读重构 PRD、本指南和该阶段涉及的现有文件；
2. 一次只实施一个阶段，不提前夹带后续阶段的大规模改动；
3. 优先复用现有内容提取、模拟器、Diff、Markdown 和可视化逻辑；
4. 每个阶段完成后执行该阶段的验收，不通过则不进入下一阶段；
5. 每次结束时记录修改文件、关键决策、验证结果和遗留项，供下一会话继续；
6. 所有阶段都只修改学习网站，不改变 `s01_*`—`s17_*` 的课程代码行为；
7. 全局搜索不得以按钮、快捷键、隐藏面板或占位入口的形式混入本期实现。

### 1.1 阶段总览

| 阶段 | 目标 | 主要交付物 |
|---:|---|---|
| 1 | 建立可靠的视觉、路由和内容基础 | Design Token、字体、全局框架、新导航、新路由、仅 17 章的数据管线 |
| 2 | 完成品牌首页和两种课程入口 | 首页、Harness 说明面板、首页模拟、Course、Topics |
| 3 | 完成核心章节学习体验 | 三栏章节页、四个 Tab、目录、源码、模拟、阅读进度 |
| 4 | 完成比较能力并统一全站体验 | Compare、章节 Diff、完整英中双语、跨页面状态与视觉一致性 |
| 5 | 完成质量收敛和基线验收 | 响应式、可访问性、动效、性能、全路由与内容检查 |
| 6 | 在稳定基线上完成个性化调整 | 用户确认的视觉、动效与交互细节优化 |

### 1.2 全阶段共同约束

- 品牌只显示 `Harness`，不再把 `Learn Claude Code` 作为品牌名；
- 西文品牌与 Display 字体使用 Space Grotesk；字体文件自托管，并保留 SIL OFL 1.1 许可；
- 使用 Obsidian、Carbon、Graphite、Chalk、Smoke 和统一的 Pulse Green 强调色设计 Token；
- 不使用常规投影、大面积彩色渐变、彩虹分类色和无意义发光；
- Display 标题默认 `font-weight: 400`，正文阅读性高于装饰性；
- 首页和所有功能界面只支持英文和简体中文；不生成日语页面、路由、切换入口或网站数据；
- 语言切换必须保留当前页面、章节和功能上下文；
- 旧版 `agents/` 与旧版 12 章文档不进入新网站的数据、路由或导航；
- 交互不能只依赖颜色表达状态；
- 每个阶段都应兼顾键盘操作和 `prefers-reduced-motion`，不能全部留到最后补救。

### 1.3 通用验证命令

每个阶段至少执行：

```bash
cd web
npm run extract
npx tsc --noEmit
npm run build
```

需要人工检查页面时：

```bash
cd web
npm run dev
```

当前项目没有独立 lint 脚本，不把不存在的 `npm run lint` 写入验收。若开发中新增测试或检查脚本，应在 `web/package.json` 和本指南中同步说明。

## 2. 阶段一：视觉基础、内容边界与站点框架

### 阶段目标

先建立后续页面共同依赖的基础，解决当前站点品牌、彩色视觉、旧路由和旧内容回退问题。完成后，网站应已经具有 Harness 的全局外观和稳定信息架构，但不要求首页与章节页全部完成。

### 主要修改范围

重点涉及：

```text
web/src/app/globals.css
web/src/app/[locale]/layout.tsx
web/src/components/layout/header.tsx
web/src/components/layout/sidebar.tsx
web/src/components/ui/*
web/src/lib/constants.ts
web/src/i18n/messages/{en,zh}.json
web/scripts/extract-content.ts
web/src/app/[locale]/(learn)/timeline/
web/src/app/[locale]/(learn)/layers/
web/public/fonts/
```

可根据现有结构新增 `styles`、`fonts` 或通用布局组件，但不要为每个页面复制一套 Token。

### 修改内容

1. **建立全局视觉系统**
   - 在 `globals.css` 或统一主题层定义 PRD 中的颜色、字体、间距、边线、圆角和动效 Token；
   - 将当前蓝、绿、紫、橙、红的 Layer 彩虹色改为白、灰和统一的 Pulse Green 点缀；
   - 将默认页面改为深色工程蓝图风格，移除与目标风格冲突的投影、渐变和大圆角；
   - 为正文、代码、表格、焦点态、滚动条和 Reduced Motion 建立基础规则。

2. **接入开源字体**
   - 从 Space Grotesk 官方来源引入实际使用的 WOFF2 字重；
   - 使用本地字体加载方式，避免运行时依赖外部 CDN；
   - 将版权声明和 `OFL.txt` 随字体保存在仓库；
   - 配置中文和等宽字体回退，确保字体未加载时页面不跳版、仍可阅读。

3. **重构全局框架与导航**
   - Logo 改为 `Harness`；
   - 顶级导航改为 `COURSE / TOPICS / COMPARE`，并保留语言切换与 `START S01`；
   - 移除与本期无关的搜索入口；
   - 桌面和移动导航使用同一数据源，当前项、焦点态和菜单开关清晰；
   - 语言切换通过替换 URL locale 保留当前路径，而不是总是返回首页；
   - 若继续保留 GitHub 链接，应作为辅助动作，不与主导航争夺层级。

4. **调整页面路由**
   - 将 `/[locale]/timeline` 调整为 `/[locale]/course`；
   - 将 `/[locale]/layers` 调整为 `/[locale]/topics`；
   - 更新所有站内链接和英中双语导航文案；
   - 确认 locale 配置、静态参数、语言切换器和 i18n 消息只保留英文与简体中文；
   - 新界面不保留 Timeline、Layers 或旧版 12 章的可见兼容入口。

5. **收紧内容提取边界**
   - `extract-content.ts` 只扫描根目录 `s01_*`—`s17_*`；
   - 移除运行时回退到 `agents/` 和旧版 12 章文档的逻辑；
   - 缺少章节、`code.py` 或必要 README 时在开发阶段明确失败；
   - 保留已有 README 链接改写、图片复制、源码统计和 Diff 生成能力；
   - 内容提取只读取 `README.md` 和 `README.zh.md`；
   - 结构数据与展示文案分离：章节顺序、依赖和层级保留在常量中，标题、说明和界面文字进入英中双语消息文件。

### 阶段验收标准

- [ ] `/en/`、`/zh/` 均能打开，页面品牌只显示 `Harness`；
- [ ] 英文和简体中文下均存在 Course、Topics、Compare、语言切换和 Start S01 导航；
- [ ] `/ja/` 不再生成或作为受支持路由，语言切换器中不存在日语；
- [ ] `/[locale]/course`、`/[locale]/topics`、`/[locale]/compare` 路由可访问；原 `/timeline`、`/layers` 页面已移除且站内不再链接；
- [ ] 语言切换后仍停留在当前功能页或当前 `sNN`；
- [ ] 页面使用黑色画布、细线边界和克制强调色，不再用五种高饱和色区分机制层；
- [ ] Space Grotesk 从本地加载，字体目录包含可核对的 OFL 许可；
- [ ] `npm run extract` 明确生成 17 个版本、34 份英中双语课程文档；
- [ ] 生成数据中不存在旧版章节 ID、旧版 12 章正文或日语正文；
- [ ] 根目录主课程不完整时提取脚本会报错，而不是静默回退旧版；
- [ ] `npx tsc --noEmit` 和 `npm run build` 通过。

### 新会话启动指令

```text
请执行 docs/Harness学习网站分阶段开发指南.md 的“阶段一：视觉基础、内容边界与站点框架”。
先完整阅读 docs/学习网站重构PRD.md 和阶段一说明，再检查 web/ 当前实现。
只完成阶段一范围，不开发首页完整内容和章节页重构。完成后按阶段验收标准检查，并列出修改文件、验证结果和遗留项。
```

## 3. 阶段二：品牌首页、课程页与主题页

### 阶段目标

完成用户第一次进入网站时的理解与探索路径。阶段结束后，用户应能在 30 秒内理解 Harness 课程讲什么，并能按顺序或按主题进入任意章节。

### 主要修改范围

重点涉及：

```text
web/src/app/[locale]/page.tsx
web/src/app/[locale]/(learn)/course/page.tsx
web/src/app/[locale]/(learn)/topics/page.tsx
web/src/components/architecture/message-flow.tsx
web/src/components/timeline/*
web/src/components/simulator/*
web/src/hooks/useSimulator.ts
web/src/i18n/messages/{en,zh}.json
```

建议按职责新增 `components/home/`、`components/course/`、`components/topics/`，但避免把每个首页小区块都拆成没有复用价值的单文件组件。

### 修改内容

1. **重做首页内容结构**
   - 完成 Hero、核心理念、四宫格价值、17 章预览、六阶段地图、核心循环和结尾行动区；
   - 首屏明确出现课程主题、`17 LESSONS` 和进入 s01 的主 CTA；
   - 首页不加载全部章节源码，仅使用必要元数据和 s01 场景；
   - 所有首页文案、按钮和模拟说明随语言完整切换。

2. **实现可操作的首页 Agent Loop**
   - 使用 `USER → MODEL → TOOL_USE → TOOL_RESULT → MODEL` 的可见路径；
   - 支持 `PLAY / PAUSE / NEXT / RESET`；
   - 动画状态与文字说明同步，复用现有 `useSimulator` 或抽取后的通用步进逻辑；
   - 使用 `transform` 和 `opacity` 为主，避免布局抖动和无意义持续动画；
   - Reduced Motion 下默认暂停并允许手动单步。

3. **实现“什么是 Harness”面板**
   - Hero 中提供小型描边按钮；
   - 桌面端从右侧展开，移动端使用底部面板；
   - 说明模型与 Harness 的职责边界，并展示五个组成项；
   - 支持关闭按钮、Esc、遮罩关闭、焦点进入与返回；
   - 不增加独立理念页面。

4. **完成 Course 页面**
   - 顺序展示 s01—s17、阶段划分、核心问题和新增机制；
   - 明确说明“阅读顺序线性，但各章源码并非全部线性累加”；
   - 里程碑章和当前章使用结构、标签与状态点共同表达；
   - 所有章节节点可以直接进入详情，不强制完成前置章节。

5. **完成 Topics 页面**
   - 按 Tools & Execution、Planning & Control、Memory Management、Concurrency & Scheduling、Multi-Agent Platform 组织章节；
   - 使用系统总线、线型和编号区分主题，不恢复彩虹色；
   - 章节归类必须与 PRD 和 `VERSION_META` 一致。

### 阶段验收标准

- [ ] 首页首屏无需滚动即可看到 Harness 定位、17 章信息和 Start S01；
- [ ] Hero 主视觉是 Agent Loop，而不是通用粒子、世界地图或静态科技背景；
- [ ] 首页模拟的播放、暂停、单步和重置均可连续使用，完成后可正常再次重置；
- [ ] 动画过程中布局不跳动，390×844 视口下没有横向溢出；
- [ ] Reduced Motion 下不自动播放位移动画，手动单步仍可用；
- [ ] “什么是 Harness”面板在桌面和移动端均可打开、关闭，并正确管理键盘焦点；
- [ ] Course 完整显示且只显示 s01—s17，顺序正确、阶段边界明确；
- [ ] Topics 的五类章节归属与 PRD 一致，所有节点都能进入正确章节；
- [ ] 英文和简体中文首页不存在固定为其他语言的标题、按钮或说明；代码标识和品牌名除外；
- [ ] 页面没有常规投影、彩色渐变或大面积绿色背景；
- [ ] `npx tsc --noEmit` 和 `npm run build` 通过。

### 新会话启动指令

```text
请执行 docs/Harness学习网站分阶段开发指南.md 的“阶段二：品牌首页、课程页与主题页”。
先确认阶段一验收已经通过，再阅读重构 PRD 的首页、课程页、主题页、动效和英中双语要求。
复用现有模拟与数据能力，不重写内容提取器。完成后逐项验证阶段二验收标准，并给出修改文件和验证结果。
```

## 4. 阶段三：章节详情与本机阅读进度

### 阶段目标

完成网站最核心的学习闭环，使每一章都能在叙事、模拟、源码和架构之间切换，并让用户始终知道当前位置、前后关系和本机进度。

### 主要修改范围

重点涉及：

```text
web/src/app/[locale]/(learn)/layout.tsx
web/src/app/[locale]/(learn)/[version]/page.tsx
web/src/app/[locale]/(learn)/[version]/client.tsx
web/src/components/layout/sidebar.tsx
web/src/components/docs/doc-renderer.tsx
web/src/components/code/source-viewer.tsx
web/src/components/simulator/*
web/src/components/architecture/*
web/src/components/visualizations/*
web/src/components/ui/tabs.tsx
web/src/data/annotations/*
web/src/data/scenarios/*
web/src/hooks/
```

### 修改内容

1. **重构章节布局**
   - 桌面端使用章节导航、主内容、页内目录三栏布局；
   - 平板隐藏或折叠右侧目录，移动端将章节导航和页内目录改为可访问抽屉；
   - Header 展示章节编号、阶段、核心洞察、机制标签和前后章节；
   - 章节结束区展示三条结论、观察重点、下一章预告和继续按钮。

2. **完善 Learn**
   - 继续从英文和中文 README 自动读取正文，不在前端维护副本；
   - 统一标题、段落、引用、代码、表格、图片和外链样式；
   - 为 H2/H3 生成稳定锚点和 Scrollspy；
   - 当前语言缺失时显示明确提示，再提供英文内容，不能静默回退；
   - 如需精简课程内容，应修改英文和中文源 README，并保持两种语言的技术事实一致。

3. **完善 Simulate**
   - 保留 17 章场景按需加载；
   - 展示用户消息、模型文本、工具调用、工具结果和系统事件；
   - 每一步均有可读注释，并与当前步骤状态同步；
   - 翻译场景标题、描述、叙事和注释；命令、代码和工具原始输出保持原样；
   - 播放、暂停、下一步、重置及 Reduced Motion 行为与首页一致。

4. **完善 Source 与 Deep Dive**
   - Source 显示完整 `code.py`、行号、文件路径、复制按钮、类/函数导航；
   - 接入现有 `annotations/sNN.json`，让重点行可定位并显示说明；
   - 支持“仅看本章新增”时，必须明确比较基准，不能把非线性章节误写成完整继承；
   - Deep Dive 保留执行流、架构图、设计决策和相关章节增量；
   - 补齐 s16、s17 缺失的章节视觉或提供同等信息量的通用架构视图。

5. **实现本机阅读进度**
   - 新增统一的进度数据层，避免页面各自直接拼装 `localStorage`；
   - 首次打开章节记为 `CURRENT`，完成阅读或点击“标记已读”后记为 `READ`；
   - Course、章节导航和 Header 使用同一进度状态；
   - 刷新和切换语言后进度保持一致，不按语言重复记录；
   - Course 页面提供“清除本机进度”，执行前二次确认；
   - `localStorage` 不可用或数据损坏时安全回退，不阻断阅读。

### 阶段验收标准

- [ ] s01—s17 均能打开 Learn、Simulate、Source、Deep Dive 四个 Tab；
- [ ] Tab 使用正确的 `tablist`、`tab`、`tabpanel` 语义，并可通过键盘切换；
- [ ] 桌面三栏互不遮挡；平板和移动端抽屉可打开、关闭、Esc 退出并恢复焦点；
- [ ] 页内目录能定位 H2/H3，滚动时当前项正确更新，固定 Header 不遮挡锚点；
- [ ] 英文和中文 README、图片、表格、引用和代码块正常渲染，缺失翻译会显示明确提示；
- [ ] 17 个模拟场景均可播放、暂停、单步和重置，步骤说明符合当前语言；
- [ ] Source 内容与对应根目录 `sNN_*/code.py` 一致，复制代码和文件路径有可读反馈；
- [ ] annotations 能定位到对应源码行，不存在越界或指向错误文件的标注；
- [ ] s16、s17 不再出现没有任何章节视觉说明的空白 Header 区；
- [ ] 首次打开、标记已读、刷新保持、跨语言保持和清除进度均符合定义；
- [ ] 禁用或模拟损坏 `localStorage` 后，页面仍可正常浏览；
- [ ] 章节正文在 390×844 下无页面级横向溢出，代码和表格自身允许横向滚动；
- [ ] `npx tsc --noEmit` 和 `npm run build` 通过。

### 新会话启动指令

```text
请执行 docs/Harness学习网站分阶段开发指南.md 的“阶段三：章节详情与本机阅读进度”。
先确认阶段一、二验收通过，再阅读 PRD 的章节页、组件、英中双语、进度和可访问性要求。
必须复用根目录 README、code.py、scenarios、annotations 和 execution-flows 数据，不手写重复正文。完成后检查全部 17 章，并输出修改文件、验证结果和未解决问题。
```

## 5. 阶段四：章节比较与全站一致性

### 阶段目标

在已有页面基础上完成章节差异探索，并清除跨页面的文案、视觉和状态不一致。该阶段不新增全局搜索。

```text
web/src/app/[locale]/(learn)/compare/page.tsx
web/src/app/[locale]/(learn)/[version]/diff/*
web/src/components/diff/*
web/src/components/architecture/*
web/src/lib/constants.ts
web/src/i18n/messages/{en,zh}.json
web/src/data/generated/versions.json（由脚本生成，不手改）
```

## 6. 阶段五：响应式、可访问性、性能与基线验收

### 阶段目标

不再扩展产品范围，集中解决质量问题，使整个重构达到稳定、可交付的产品基线。阶段五的缺陷必须在本阶段修复，不能留给阶段六用“个性化调整”代替。

### 主要修改范围

本阶段允许修改所有 `web/` 展示文件，但改动必须服务于验收缺陷，不进行无关架构重写、依赖升级或新增功能。

### 修改内容

1. **响应式收敛**
   - 检查 PRD 规定的六类视口；
   - 修复 Header、Hero、面板、三栏章节、Tabs、代码、表格、架构图和 Diff 的遮挡或溢出；
   - 确保触控目标不小于 44×44px，固定 Header 不覆盖正文锚点。

2. **可访问性收敛**
   - 检查 Skip to Content、标题层级、Landmark、按钮名称、图片替代文本和焦点可见性；
   - 完成 Tabs、抽屉、Harness 面板和模拟器的键盘流程；
   - 动态状态提供文字或非打断式反馈；
   - 200% 缩放后仍可完成导航、学习、模拟、复制和比较。

3. **动效与性能收敛**
   - Reduced Motion 下停止自动位移、平滑滚动和持续流动，只保留必要状态变化；
   - 检查首页没有加载 17 份完整源码，章节场景和大型视觉按需加载；
   - 避免字体、图片和懒加载组件造成明显布局位移；
   - 修复动画掉帧、重复定时器、切页后仍播放和快速操作状态错乱。

4. **内容与路由总验收**
   - 自动提取结果严格为 s01—s17；
   - 检查英中双语首页、功能页、17 章和关键 Diff；
   - 检查 README 图片、内部链接、前后章节和语言切换；

## 7. 阶段六：个性化视觉、动效与交互调整

### 阶段目标

在前五个阶段全部通过、网站功能和质量基线稳定后，根据用户明确确认的偏好调整视觉节奏、品牌表达、动效和交互细节。该阶段用于个性化打磨，不用于补做前五阶段遗漏的核心功能或验收缺陷。

### 主要修改范围

可修改 `web/` 中与已确认调整项直接相关的展示文件。每项改动都应能够对应到用户确认的调整清单，避免无关重构、依赖升级或内容管线改写。

### 修改内容

1. **建立个性化调整清单**
   - 开始开发前，由用户确认页面位置、触发方式、期望效果、持续时间、是否循环、移动端表现和 Reduced Motion 行为；
   - 将调整项区分为视觉、动效、交互反馈和内容节奏，逐项实施、逐项验收；
   - 未经确认不擅自增加新的产品功能或改变既有信息架构。

2. **调整视觉与品牌表达**
   - 可按确认结果调整构图、留白、字号比例、结构线、节点密度和局部强调；
   - 保持 Harness 品牌、黑色工程蓝图、英中双语和 s01—s17 内容边界；
   - 不恢复常规投影、大面积彩色渐变、彩虹分类色或与 Agent Harness 无关的装饰视觉。

3. **调整动效与交互反馈**
   - 可优化 Hero、Agent Loop、面板、课程路径、主题总线、章节模拟和 Compare 的过渡与反馈；
   - 动效必须帮助理解信息流、层级或状态，优先使用 `transform` 和 `opacity`；
   - 循环动画必须可停止，交互动画不能造成布局抖动、操作阻塞或状态错乱；
   - Reduced Motion 下停止自动位移和持续动画，同时保留文字状态与手动操作能力。

4. **守住产品与质量边界**
   - 不改变课程 README、`code.py` 和生成内容的事实来源；
   - 不加入全局搜索、登录、云端进度、在线 Agent、部署或其他排除项，除非另行修改 PRD 并明确立项；
   - 个性化调整不得破坏键盘操作、焦点管理、响应式、英中双语、性能和可访问性。

- [ ] 390×844 与六类基线视口下无页面级横向溢出、遮挡或布局跳动；
- [ ] 键盘操作、Esc 关闭、焦点返回和 200% 缩放下核心流程仍可用；
- [ ] Reduced Motion 下没有自动位移或持续流动，手动单步和状态反馈仍可用；
