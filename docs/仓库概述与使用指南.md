# Learn Claude Code：仓库概述与使用指南

> 本文基于当前仓库结构整理。仓库已经存在 `docs/` 目录，因此本文直接存放于该目录中。

## 1. 项目简介

`learn-claude-code` 是一个从零构建 **Agent Harness（智能体运行载体）** 的教学仓库。它不是 Claude Code 源码复刻，也不是可直接用于生产环境的完整编码 Agent。

仓库的核心观点是：

```text
Agent 产品 = 模型 + Harness

Harness = Tools + Knowledge + Observation + Action Interfaces + Permissions
```

模型负责推理和决策；Harness 负责提供工具、上下文、权限边界、持久状态以及与外部环境交互的接口。

整个课程围绕一个最小 Agent Loop 展开：

```python
while True:
    response = call_model(messages, tools)
    messages.append(response)

    tool_calls = find_tool_calls(response)
    if not tool_calls:
        return

    results = execute_tools(tool_calls)
    messages.append(results)
```

模型输出 `tool_use` 时，Harness 执行工具并把结果放回 `messages`；模型不再调用工具时，本轮结束。后续章节在这个循环周围逐步加入权限、Hooks、规划、上下文管理、持久记忆、任务系统、多 Agent 协作、MCP、工作流和目标闭环。

## 2. 仓库定位与特点

- **教学优先**：每章集中说明一个机制，代码刻意保持直观，不追求生产级封装。
- **渐进式课程**：当前主线为根目录下的 `s01`—`s17`。
- **章节可独立运行**：每章都有 `code.py`，便于单独阅读和实验。
- **三语文档**：每章包含英文、中文和日文 README。
- **真实模型调用**：通过 Anthropic Python SDK 调用 Anthropic 兼容接口；示例默认配置为 DeepSeek。
- **配套 Web 平台**：可查看课程、源码、模拟过程、架构图及版本差异。
- **自动化测试**：测试覆盖 Agent Loop 边界、任务状态、后台执行、定时调度、团队运行时、工作流恢复和 Goal Loop 等关键行为。

## 3. 课程主线

| 章节 | 主题 | 主要内容 |
|---|---|---|
| `s01_agent_loop` | Agent Loop | 最小模型—工具循环，只提供 Bash |
| `s02_tool_use` | Tool Use | 文件工具、Glob 和统一 dispatch map |
| `s03_permission` | Permission | 拒绝列表、规则匹配和用户审批 |
| `s04_hooks` | Hooks | `UserPromptSubmit`、`PreToolUse`、`PostToolUse`、`Stop` |
| `s05_todo_write` | TodoWrite | 会话内计划、状态更新和提醒机制 |
| `s06_subagent` | Subagent | 使用全新 `messages[]` 执行一次性子任务 |
| `s07_skill_loading` | Skill Loading | 扫描技能目录并按需加载 `SKILL.md` |
| `s08_context_compact` | Context Compact | 大结果转存、历史裁剪、微压缩和摘要 |
| `s09_memory` | Memory | 记忆选择、提取、持久化和整理 |
| `s10_task_system` | Task System | 文件化任务图、依赖、认领和完成状态 |
| `s11_background_tasks` | Background Tasks | 显式后台 Bash 和完成通知注入 |
| `s12_cron_scheduler` | Cron Scheduler | 五段式 Cron、持久任务和至少一次交付 |
| `s13_agent_teams` | Agent Teams | Lead、持久队友、消息总线、原子认领和 Worktree |
| `s14_mcp_plugin` | MCP Plugin | 外部工具发现、命名空间和宿主权限策略 |
| `s15_integrated_harness` | Integrated Harness | 将前述机制组装进同一个运行时 |
| `s16_workflow_runtime` | Workflow Runtime | 固定编排、并行、结构化输出、Journal 和恢复 |
| `s17_goal_loop` | Goal Loop | 独立判断器检查目标，未完成时自动续轮 |

### 3.1 章节之间并非简单累加

学习顺序是 `s01` 到 `s17`，但源码并不是每章都完整复制上一章：

- `s11` 和 `s12` 分别单独讲后台执行与定时调度；
- `s13` 聚焦任务系统和团队协作，没有带入 `s11`、`s12`；
- `s14` 从较小的 Hooks 内核出发，单独讲 MCP，使用的是进程内模拟 Server，不包含真实 MCP Transport；
- `s15` 才把工具、权限、技能、记忆、任务、后台、Cron、团队、Worktree 和 MCP 等机制集成起来；
- `s16` 把可恢复 Workflow 作为工具安装进 `s15` 宿主；
- `s17` 是以较小内核单独讲解 Goal Stop Hook 的示例，概念上可以与 `s16`、`s15` 组合，但本章不是另一个全量集成运行时。

因此，比较代码时应同时阅读每章 README 中的“相对上一章的变化”和“边界”说明。

## 5. 运行环境

### 5.1 Python

推荐使用 **Python 3.11**，这也是仓库 CI 使用的版本。

部分说明写的是 Python 3.9 以上，但当前章节源码中使用了 `X | None` 等类型注解；完整运行主线时应至少使用 Python 3.10。为减少解释器差异，建议直接使用 3.11。

检查版本：

```bash
python3 --version
```

> `run.py` 固定使用项目内的 `.venv`。如果 `.venv` 已由旧版 Python 创建，仅激活另一个环境不会改变 `run.py` 的选择，需要使用 Python 3.10+ 重新创建项目的 `.venv`。

### 5.2 平台和其他工具

- 推荐 macOS 或 Linux；`s13`、`s15`、`s16` 使用了 `fcntl` 和 Unix 风格的进程/文件锁。
- `s13`、`s15` 的 Worktree 实验需要 Git，且当前目录需要是 Git 仓库。
- Web 平台建议使用 Node.js 20，与 CI 配置一致。
- 安装依赖和调用模型需要联网。
- 调用模型通常会产生 API 费用，子 Agent、记忆提取、Goal 判断和 Workflow 都可能产生额外请求。

### 5.3 Python 依赖

`requirements.txt` 包含：

| 包 | 用途 |
|---|---|
| `anthropic` | Anthropic Messages API 客户端 |
| `python-dotenv` | 加载 `.env` 配置 |
| `pyyaml` | 解析 Skill 的 YAML Frontmatter |

`pytest` 只用于开发测试，不在运行依赖中，需要单独安装。

## 6. 快速开始

### 6.1 推荐方式：使用启动器

在仓库根目录执行：

```bash
python3 run.py
```

首次运行时，启动器会：

1. 在项目 `.venv` 中安装依赖；
2. 使用清华 PyPI 镜像下载依赖；
3. 检查 `ANTHROPIC_API_KEY`；
4. Key 缺失时提示输入，并写入根目录 `.env`；
5. 显示 `s01`—`s17` 菜单。

在菜单中：

```text
s01        进入第一章
3          进入 s03
key        重新设置 API Key
list       重新显示课程列表
q          退出启动器
```

进入普通课程后，输入 `q`、`exit` 或空行通常会退出当前章节并返回菜单。

macOS 也可以双击根目录的 `启动.command`。它会切换到仓库根目录并运行 `python3 run.py`。

### 6.2 手动创建环境

如果希望显式管理环境：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

# 仅在 .env 尚不存在时复制模板
[ -f .env ] || cp .env.example .env
```

然后编辑 `.env`，填入有效 API Key，再运行：

```bash
python run.py
```

### 6.3 直接选择章节

```bash
python run.py list              # 只显示课程列表
python run.py 3                 # 运行 s03
python run.py s03               # 同上
python run.py agent_loop        # 按目录关键词匹配 s01
python run.py setkey            # 重新设置 API Key
```

启动器会把章节名之后的参数原样转发给该章，例如：

```bash
python run.py s16 demo
python run.py s16 resume
python run.py s17 "/goal python -m pytest 退出码为 0"
```

### 6.4 绕过启动器，直接运行源码

在仓库根目录执行：

```bash
source .venv/bin/activate
python s01_agent_loop/code.py
python s15_integrated_harness/code.py
```

各章通常使用 `Path.cwd()` 作为 Agent 工作区，因此应先切换到希望 Agent 操作的目录。通过 `run.py` 启动时，工作区固定为仓库根目录。

## 7. API 配置

根目录 `.env.example` 默认使用 DeepSeek 的 Anthropic 兼容接口：

```dotenv
ANTHROPIC_API_KEY=你的_API_Key
ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
MODEL_ID=deepseek-chat
```

主要变量：

| 变量 | 是否必需 | 说明 |
|---|---:|---|
| `ANTHROPIC_API_KEY` | 是 | 模型服务 API Key |
| `ANTHROPIC_BASE_URL` | 否 | Anthropic 兼容端点；示例默认使用 DeepSeek |
| `MODEL_ID` | 否 | 主模型，默认 `deepseek-chat` |
| `FALLBACK_MODEL_ID` | 否 | `s15` 在特定服务错误后可使用的备用模型 |
| `GOAL_EVALUATOR_MODEL_ID` | 否 | `s17` 独立 Goal 判断器使用的模型 |
| `MAX_TURNS` | 否 | `s17` 主循环最大轮数；`0` 表示不设置该限制 |
| `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` | 否 | `s17` Stop Hook 连续阻止结束的上限，默认 8 |

切换到 Claude 官方接口时，可以改为：

```dotenv
ANTHROPIC_BASE_URL=https://api.anthropic.com
MODEL_ID=你的_Claude_模型_ID
```

注意：

- `.env` 已在 `.gitignore` 中排除，不要把 Key 写入 README、代码或提交记录。
- `python run.py setkey` 会覆盖 `.env` 中的 `ANTHROPIC_API_KEY`。
- 其他供应商必须兼容项目使用的 Anthropic Messages API 和 Tool Use 格式。

## 8. 建议的学习方法

每章建议按照以下顺序学习：

1. 阅读该章 `README.zh.md`，先理解问题和设计边界；
2. 阅读 `code.py` 的模块说明、工具定义和 `agent_loop`；
3. 运行 README “试一下”部分提供的 Prompt；
4. 观察终端中的工具调用、Hook、权限询问和通知；
5. 检查章节生成的本地状态文件；
6. 与相关前置章节比较，确认新增机制插在循环的哪个位置；
7. 完成前置章节后再阅读 `s15` 的集成实现。

一个较实用的分阶段路径是：

- **基础执行**：`s01`—`s04`
- **规划与上下文**：`s05`—`s08`
- **跨会话状态**：`s09`—`s10`
- **并发与调度**：`s11`—`s12`
- **多 Agent 与外部能力**：`s13`—`s14`
- **集成、编排与目标闭环**：`s15`—`s17`

## 9. 特殊章节使用说明

### 9.1 s09：持久记忆

运行：

```bash
python run.py s09
```

可以先告诉 Agent 一个长期偏好，退出并重启后再询问。记忆保存在 `.memory/`：

```text
.memory/MEMORY.md     # 记忆索引
.memory/*.md          # 单条记忆正文
```

Memory 是选择性的长期知识，不是完整聊天记录。

### 9.2 s10：持久任务图

任务保存在 `.tasks/task_*.json`，包含状态、负责人和 `blockedBy`。依赖图需要分两阶段构建：先创建所有任务取得真实 ID，再用这些 ID 建立依赖。

### 9.3 s11：后台命令

只有模型明确给 Bash 设置 `run_in_background=true` 时才会进入后台。工具调用先返回 `bg_id`，完成结果在后续轮次以 `<task_notification>` 注入。

`s11` 的后台结果本身不会主动唤醒已经结束的循环；`s15` 的集成 CLI 才会监听后台完成事件并自动唤醒。

### 9.4 s12：定时任务

```bash
python run.py s12
```

支持五段式 Cron，以及 `*`、`*/N`、单值、范围和逗号列表。持久任务保存在 `.scheduled_tasks.json`。

限制：

- 使用运行进程所在机器的本地时间；
- 进程退出后不再检查时间；
- 重启后不会补跑停机期间错过的时间点；
- `durable` 只表示任务定义会恢复，不表示存在系统级常驻调度器。

### 9.5 s13：Agent Teams 和 Worktree

运行：

```bash
python run.py s13
```

Lead 应先提出团队方案，用户确认后才启动队友。运行过程中可观察：

```text
.tasks/             # 共享任务记录
.mailboxes/         # Lead 与队友的 JSONL 收件箱
.worktrees/         # 绑定到任务的可选 Git Worktree
```

Worktree 只隔离 Git 工作目录，不是安全沙箱。队友仍拥有当前操作系统用户可访问的资源。

### 9.6 s14：MCP

课程内置的 `docs` 和 `deploy` 是模拟 Server，用于说明工具发现、`mcp__server__tool` 命名和权限策略，并未实现真实 MCP Transport。

示例 Prompt：

```text
连接 docs server，搜索 agent hooks，并告诉我当前文档 API 版本。
```

### 9.7 s15：集成 Harness

```bash
python run.py s15
```

这一章适合在完成前述机制后阅读。它把用户输入、Cron、后台通知、团队事件、上下文压缩、Memory、Skills、MCP 和工具结果统一送回同一个 Agent Loop。

`s15` 中每条 Bash 命令都会经过权限确认；异步线程不会与主终端争抢输入，需要交互确认的异步操作会被拒绝。

### 9.8 s16：Workflow Runtime

交互模式使用真实 API：

```bash
python run.py s16
```

无需真实 API 请求即可观察确定性演示：

```bash
python s16_workflow_runtime/code.py demo
python s16_workflow_runtime/code.py resume
```

`demo` 执行内置 `review-changes` 工作流；`resume` 使用上一次 Run ID，已完成且调用内容未变化的 `agent()` 会命中 Journal 缓存。也可以使用 `python run.py s16 demo`，但启动器仍会先检查依赖和 API Key。

运行产物位于：

```text
s16_workflow_runtime/.runtime/
├── <runId>.json
├── <runId>.output.json
├── <runId>.journal.jsonl
└── <runId>.lock
```

### 9.9 s17：Goal Loop

交互设置目标：

```bash
python run.py s17
```

```text
/goal pytest tests/auth 退出码为 0，并且 lint 没有错误
/goal                 # 查看当前目标
/goal clear           # 清除目标
```

也可以直接提交：

```bash
MAX_TURNS=20 python run.py s17 \
  "/goal 修复类型错误，直到 npm run typecheck 退出码为 0"
```

Goal 判断器不能调用工具，只能读取对话中已有的命令和结果，因此完成条件应明确写出结束状态、验证方式和限制条件。

## 13. 安全边界

运行课程前需要明确以下风险：

1. **Agent 会执行模型生成的 Shell 命令并修改文件。** 建议在可恢复的实验副本中学习。
2. **权限实现是教学示例，不是完整沙箱。** 简单字符串拒绝列表不能覆盖命令别名、编码、脚本间接调用和所有外部副作用。
3. **文件工具的工作区限制不等于 Shell 隔离。** Bash 仍可能访问当前用户有权限访问的其他路径、网络和进程。
4. **Git Worktree 不是安全隔离。** 它只提供独立 Working Copy 和分支。
5. **MCP 描述不能作为授权依据。** 课程通过宿主策略区分只读和需确认工具；接入真实 Server 时也应保持此原则。
6. **异步和 Cron 可能重复交付。** `s12`、`s15` 采用至少一次语义，任务应尽量具备幂等性。
7. **API Key 只能保存在本地环境配置中。** 不要打印、分享或写入代码。

## 14. 常见问题

### API 返回 401 或 authentication 错误

重新设置 Key：

```bash
python run.py setkey
```

同时检查 `ANTHROPIC_BASE_URL`、`MODEL_ID` 与 Key 是否属于同一供应商。

### 已激活虚拟环境，但 `run.py` 仍使用其他 Python

`run.py` 优先调用项目固定路径 `.venv/bin/python`，而不是当前 Shell 中任意名称的环境。检查：

```bash
.venv/bin/python --version
```

如版本过旧，应使用 Python 3.10+ 重新创建项目 `.venv`，推荐 3.11。

### 安装依赖失败

手动执行：

```bash
.venv/bin/python -m pip install -r requirements.txt
```

启动器默认使用清华镜像；网络无法访问该镜像时，可以改用环境可访问的 PyPI 源。

### 出现 `socksio package is not installed`

当前系统若通过 SOCKS 代理访问网络，HTTPX 还需要 SOCKS 可选依赖：

```bash
.venv/bin/python -m pip install "httpx[socks]"
```

### 直接运行章节时找不到 Skill 或操作了错误目录

课程把当前工作目录当作 `WORKDIR`。先返回仓库根目录再运行：

```bash
cd /path/to/learn-claude-code
python s07_skill_loading/code.py
```

### Cron 在退出程序后没有继续运行

这是课程设计边界。进程结束后调度线程会停止；需要真正常驻的调度，应使用 crontab、systemd timer 或云调度服务。

### Worktree 创建失败

确认当前目录是 Git 仓库、任务仍处于 `pending`、任务未被认领、Worktree 名称合法，并检查是否已有同名分支、目录或已注册 Worktree。

### Web 页面内容未更新

重新提取课程内容：

```bash
cd web
npm run extract
npm run dev
```

## 15. 二次开发建议

这个仓库强调“一个章节只讲清一个机制”。修改时应遵循现有贡献约定：

- 优先修改当前根目录 `sNN_topic/`，不要把旧版 `agents/` 当作主线；
- 保持教学代码最小，不无关地加入生产级抽象；
- 同步维护每章英、中、日三份 README；
- 三种语言 README 中的代码块应保持一致；
- 修改后运行 Python 测试和 Web 类型检查/构建；
- 新增 Harness 能力时，优先通过工具注册、Handler 或 Hook 扩展，避免让核心 Agent Loop 膨胀。

## 16. 总结

这个仓库展示的不是“如何用流程代码替模型思考”，而是“如何为模型构建一个可观察、可操作、可约束、可恢复的运行环境”。

最值得掌握的主线是：

```text
最小循环
→ 工具与权限
→ Hooks 与规划
→ 上下文与记忆
→ 持久任务与异步执行
→ 多 Agent 与外部工具
→ 集成运行时
→ 可恢复编排
→ 目标驱动的停止条件
```

如果只想快速理解架构，建议阅读 `s01`、`s04`、`s08`、`s10`、`s13`、`s15`、`s16`、`s17`；如果要真正实现自己的 Harness，则应按 `s01`—`s17` 顺序运行并比较每章代码。
